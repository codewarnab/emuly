Three steps, one of them yours

You paste a prompt. Your agent does the setup. You watch a phone appear.

01

Connect

One GitHub approval. The scope is Codespaces only — no repo, no code, nothing else.

02

Boot

We create a slot in your own account, install Android, and resume from a saved snapshot in about 15 seconds.

03

Watch

You get a stream URL. Tap, type, drag, or let the agent drive. Leaving is safe — the phone is still there when you come back.

What the agent gets

A skill file, four endpoints, and real adb behind them.

POST   /v1/phones              → { id, adb, stream_url }
GET    /v1/phones/:id/screenshot
POST   /v1/phones/:id/tap       { x, y }
POST   /v1/phones/:id/stop      → snapshot, keep the phone, stop billing

Real Android, real adb

API 36 with Google APIs. Your existing scripts and tests work unchanged.

Snapshot boot

About 15 seconds back to a working phone, with your app still installed.

Take over anytime

Agents pause when you touch the screen and resume when you hand back.

Zero repo access

The token can only manage codespaces. It cannot read your code, and nothing is deleted automatically.

Default: stop, don't wipe

The phone's disk and snapshot stay on your slot. Nothing to clean up, and the next boot resumes in about 15 seconds.

On request: named backups

keep.sh saves hash-checked copies beside the live phone, so one bad save cannot destroy the only good one. About 2–3 GB each, two kept.
